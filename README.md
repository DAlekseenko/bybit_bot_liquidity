# Bybit Liquidity Bot

MVP алгоритмического торгового бота на Go для проверки стратегии, использующей
свечи, open interest и ликвидации Bybit. Целевая среда — Bybit Testnet, один
линейный инструмент (`BTCUSDT` в примере конфигурации).

> **Состояние проекта:** это компилируемый каркас, но ещё не работающий торговый
> бот. Запуск загружает конфигурацию, пишет сообщение `bot initialized` и ждёт
> завершения. Адаптер Bybit умеет читать публичные свечи и open interest, но не
> подключён к `main`; приватные методы возвращают `ErrNotImplemented`, торговый
> цикл, WebSocket и SQLite отсутствуют. Не используйте проект для реальных средств.

## Что уже есть

- доменные типы и интерфейс биржи;
- публичные Bybit V5 REST-запросы linear 1m candles и open interest с unit-тестами;
- сборка снимка свечей и open interest;
- правила сигналов `LONG`/`SHORT`/`NONE` и unit-тесты;
- расчёт фиксированного риска, SL/TP и unit-тесты;
- исполнение сигнала с проверкой открытой позиции и cooldown;
- SQL-схема для сделок и сигналов, расчёт статистики;
- конфигурация Testnet, JSON-логирование и Dockerfile.

Разрыв между компонентами и готовым MVP перечислен в
[архитектуре](docs/ARCHITECTURE.md#текущее-состояние-и-разрывы).

## Требования

- Go 1.24 или новее в пределах совместимости модуля;
- Git — только для получения и совместной разработки рабочей копии;
- Docker — опционально, для контейнерной сборки.

У модуля пока нет внешних Go-зависимостей. SQLite указан как целевое хранилище,
но драйвер ещё не выбран и не подключён (`TODO`).

## Установка и быстрый запуск

Получите рабочую копию репозитория и из её корня выполните:

```bash
go test ./...
go run ./cmd/bot -config configs/config.yaml
```

Ожидаемый результат — JSON-запись об инициализации. Процесс продолжит ждать
`SIGINT`/`SIGTERM`; остановите его `Ctrl+C`. Сетевые запросы и ордера при текущей
реализации не выполняются.

Контейнерный вариант:

```bash
docker build -t bybit-liquidity-bot .
docker run --rm --name bybit-liquidity-bot bybit-liquidity-bot
```

В образ копируется [configs/config.yaml](configs/config.yaml), а команда по
умолчанию использует `/app/configs/config.yaml`.

## Конфигурация

Версионируемый пример безопасно указывает на Testnet. Секретов в нём нет, и
текущая модель конфигурации вообще не содержит API key/secret. Переменные
окружения также не читаются. До реализации приватных запросов нужно определить
механизм секретов и аутентификации; см. открытые решения в
[docs/DECISIONS.md](docs/DECISIONS.md#открытые-решения).

Текущий загрузчик поддерживает используемое проектом простое подмножество YAML,
а не произвольный YAML. Все поля и правила локальной настройки описаны в
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#конфигурация-и-переменные-окружения).

## Безопасность

Сохраняйте `exchange.testnet: true`. Не коммитьте ключи, `.env` и файлы базы из
`data/`; они исключены через `.gitignore`. Реальная торговля, модель разрешений
API-ключа и аварийное отключение не спроектированы и остаются вне текущей
готовности проекта.
