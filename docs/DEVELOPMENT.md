# Локальная разработка

Инструкции предполагают запуск из корня репозитория. Общий статус проекта и
самый короткий запуск приведены в [README.md](../README.md).

## Окружение

Обязательно:

- Go 1.24+; версия модуля зафиксирована в [go.mod](../go.mod);
- POSIX-совместимая командная строка для приведённых примеров.

Опционально:

- Docker для воспроизводимой сборки образа;
- SQLite-инструменты появятся после выбора драйвера и способа диагностики базы
  (`TODO`).

Загрузка Go-зависимостей сейчас не нужна: `go.mod` содержит только имя модуля и
версию Go. При появлении зависимостей используйте стандартный `go mod download`,
а `go.mod` и `go.sum` изменяйте вместе.

## Запуск и сборка

```bash
go run ./cmd/bot -config configs/config.yaml
go build ./...
```

Запущенный процесс только проверяет конфигурацию, пишет логи и ждёт сигнала ОС.
Остановите его `Ctrl+C`. Отсутствие торговых действий сейчас ожидаемо.

Docker:

```bash
docker build -t bybit-liquidity-bot .
docker run --rm --name bybit-liquidity-bot bybit-liquidity-bot
```

Чтобы передать другой файл, его сначала нужно сделать доступным контейнеру и
заменить аргумент entrypoint, например:

```bash
docker run --rm \
  -v "$PWD/configs:/app/configs:ro" \
  bybit-liquidity-bot -config /app/configs/config.yaml
```

`Dockerfile` собирает бинарник в `golang:1.24-alpine` и запускает его в
`alpine:3.22`. Публикация образа и production-параметры не настроены.

## Конфигурация и переменные окружения

Канонический пример — [configs/config.yaml](../configs/config.yaml).

| Секция | Ключи, которые читает код |
| --- | --- |
| корень | `symbol` |
| `exchange` | `testnet`, `base_url`, `websocket_url` |
| `strategy` | `oi_growth_percent`, `volume_multiplier`, `liquidation_threshold` |
| `risk` | `risk_per_trade_percent`, `stop_loss_percent`, `take_profit_percent` |
| `storage` | `driver`, `dsn` |
| `logging` | `level` |

Загрузчик написан на стандартной библиотеке и понимает только текущую плоскую
структуру секций и некавыченные скалярные значения. Не используйте anchors,
массивы, многострочные значения или сложное вложение YAML. Неизвестные секции и
ключи сейчас молча игнорируются; известные числовые ключи должны содержать
корректные числа.

Проверяются обязательный `symbol`, положительность и конечность числовых порогов.
URL, DSN, уровень логирования и согласованность `testnet` с URL не валидируются
(`TODO`).

Переменные окружения не поддерживаются. `.env` исключён из Git, но приложение его
не загружает. До приватных запросов требуется выбрать имена переменных, порядок
приоритетов file/env/flags и способ безопасного хранения секретов (`TODO`).

## Миграции и локальные данные

DDL находится внутри `storage.Store.Migrate` в
`internal/storage/storage.go`. Метод идемпотентно создаёт таблицы `trades` и
`signals`, но:

- SQLite-драйвер отсутствует в `go.mod`;
- `Store.Open` и `Migrate` не вызываются из приложения;
- отдельных версий миграций и команды миграции нет.

Поэтому сейчас нет рабочей команды миграции. Не предлагайте запускать выдуманный
CLI. После выбора драйвера нужно определить версионирование схемы, транзакционность
и момент запуска миграций (`TODO`). Файлы `data/*.db` и сопутствующие WAL/SHM
артефакты игнорируются; `data/.gitkeep` сохраняет каталог.

## Тесты и статический анализ

Полный локальный набор:

```bash
go test ./...
go test -race ./...
go vet ./...
go build ./...
```

Тесты сейчас покрывают `config`, `strategy`, `risk`, `execution` и public REST
Bybit-адаптера. Адаптер тестируется через fake `http.RoundTripper`, без сокетов и
реальных сетевых запросов. Покрытие `marketdata`, `storage`, `logger` и
composition root отсутствует.

Для отчёта покрытия:

```bash
go test -cover ./...
```

Отдельный линтер и порог покрытия не настроены (`TODO`). `go vet` — единственная
репозиторно подтверждённая статическая проверка сверх компилятора.

Workflow [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) выполняет
форматирование, unit-тесты, race detector, `go vet` и сборку на каждом push и
pull request.

## Форматирование

Изменённые Go-файлы форматируйте стандартным инструментом:

```bash
gofmt -w path/to/file.go
```

Проверка всего исходного дерева без записи:

```bash
test -z "$(gofmt -l cmd internal)"
```

Markdown-форматтер не настроен. Сохраняйте относительные ссылки и проверяйте, что
их цели существуют.

## Рабочий процесс

1. Сверьте задачу с [.ai/CURRENT_TASK.md](../.ai/CURRENT_TASK.md) и границы с
   [ARCHITECTURE.md](ARCHITECTURE.md).
2. Изменяйте минимальный набор пакетов, сохраняя направление зависимостей.
3. Добавляйте тесты без реального Bybit API.
4. Запустите форматирование и проверки выше.
5. Обновите соответствующий канонический документ и
   [.ai/HANDOFF.md](../.ai/HANDOFF.md).

Makefile, скрипты релиза, отдельный линтер, порог покрытия и интеграционная среда
Testnet отсутствуют. Их политика остаётся открытой задачей.
