# ADR-001: Общий движок и подключаемые стратегии

- **Статус:** принято владельцем 2026-11-21.
- **Заменяет:** правило «Liquidity и Momentum — изолированные контуры, код не
  смешивать» (действовало, пока в репозитории было два бота).

## Контекст

Цель проекта ([PROJECT_GOAL.md](../../PROJECT_GOAL.md)) — надёжно исполнять заранее
утверждённый алгоритм на Bybit. Владелец хочет один движок биржи и
отдельно подключаемые алгоритмы-стратегии, а не отдельного бота на каждую
стратегию. Прежний бот Liquidity был именно таким отдельным ботом со своими
хранилищем, paper-trade и исполнением; он не работал и удалён (тег
`legacy-liquidity-final`).

Momentum — первая стратегия. Её код лежит в `internal/momentum/*`, где общие
механизмы перемешаны с правилами Momentum. Пример: проекция дельт
`planner.ProjectBaselineDeltas` — механизм движка — вызывает
`config.CanonicalSymbols`, который требует ровно три символа.

## Решение

### Стратегия

Стратегия — чистая функция без I/O:

```
(рыночный срез, PortfolioSnapshot, параметры стратегии) → TradePlan
```

Стратегия объявляет:

| Что | Пример Momentum |
| --- | --- |
| Идентичность и версия | `strategy_id: momentum-v1`, `model_id: roc30`, профиль |
| Universe | три USDT perpetual из конфига |
| Расписание cutoff | понедельник 00:00 UTC после закрытия воскресной свечи |
| Нужные данные | дневные свечи (31), funding, mark price |
| Параметры и их проверка | плечо, доля `equity/3`, комиссия для резерва |
| Правило расчёта целей | ROC30 → активные символы → baseline-цели |

Стратегия не знает о бирже, хранилище, расписании запуска и исполнении. Она не
может вызывать биржу.

### Движок

Всё остальное — движок, общий для всех стратегий:

- адаптер биржи, импорт и заморозка данных, проверка свежести;
- `PortfolioSnapshot`, хранение планов и ревизий;
- проекция дельт и биржевые шаги (`qtyStep`, min/max);
- execution adapters: simulated (backtest, paper) и биржевой (Testnet, позже Mainnet);
- ledger, equity, risk controller, kill switch, reconciliation;
- отчёты и операторский контроль.

Только execution engine размещает, отменяет и заменяет заявки.

### Шов — `model.TradePlan`

Неизменяемый `TradePlan`: метаданные (`StrategyID`, run, profile, model,
formula, config hash, `ScheduledAt`, `EquityCutoffAt`, ревизия) и целевые
количества `Target{Symbol, Quantity}`. Движок приводит портфель к целям, а
стратегия не описывает, как это сделать.

Текущие ограничения формата, которые расширяются отдельными ADR, когда появится
стратегия, которой это нужно:

- `Quantity ≥ 0` — только LONG или кэш; SHORT потребует знаковых целей;
- нет защитных заявок (SL/TP) и событийных (внутри цикла) планов;
- одна стратегия на счёт; распределение капитала между стратегиями вне MVP.

## Правила до переноса пакетов

1. Новый код движка не вводит допущений Momentum: число символов, недельный
   цикл, ROC30, доля `equity/3`. Такие значения приходят от стратегии
   параметрами.
2. Новая логика стратегии пишется в `internal/momentum/planner` или
   `internal/momentum/signals`.
3. Перенос пакетов — отдельный механический PR без изменения поведения: движок
   в `internal/engine/...`, стратегия в `internal/strategies/momentum/...`.
   Выполняется после M1 или при старте второй стратегии.
4. Исполнение (этап M4: Testnet — класс B, Mainnet — класс C) проектируется
   для любого `TradePlan`, а не для Momentum.

## Последствия

- Вторая стратегия (например, идея ликвидаций из legacy) подключается как новый
  planner без нового хранилища и исполнения.
- Код Momentum, где механизм движка смешан с правилами стратегии, исправляется
  по мере касания, а не одной большой переделкой.

## Отклонённые варианты

- **Перенести пакеты сейчас.** Около 25 тысяч строк, конфликт с текущими Issue,
  а границы надёжнее проводить, когда есть вторая стратегия.
- **Отдельный бот на каждую стратегию.** Дублирует данные, ledger, исполнение и
  восстановление — так был устроен удалённый legacy-бот.
