# CM-002: точная decimal арифметика

`model.Decimal` хранит сокращённую дробь `math/big.Rat` без преобразования в
`float64`. Нулевое значение структуры невалидно; для нуля используйте `Zero()`.
Тип безразмерный: выбор USDT, price, Qty и rate остаётся ответственностью
вызывающего кода.

`ParseAmount` принимает signed USDT, в том числе отрицательный ledger cashflow;
`ParseRate` принимает signed долю. `ParsePrice` требует значение `> 0`, а
`ParseQty` — `>= 0`. Парсер принимает ASCII-форму
`-?(0|[1-9][0-9]*)(\.[0-9]+)?`, максимум 128 байт и 64 цифры после точки.
Пробелы, `+`, экспонента, `NaN`, `Inf`, `.005` и `1.` отклоняются; `-0`
нормализуется в `0`. Числитель и знаменатель результатов ограничены 4096 битами.

`Mul`, `Quo` и `Cmp` работают точно; деление на ноль завершается ошибкой.
`CanonicalRatio` возвращает сокращённые строки числителя/знаменателя, включая
`0/1` и `n/1`. `WireDecimal` и `MarshalText` сериализуют только конечные
десятичные значения без экспоненты и лишних нулей. Периодическая дробь
отклоняется; `MarshalJSON` выдаёт decimal как JSON-строку. JSON decoding,
`Add` и `Sub` не входят в контракт.

Перед `MeetsMinNotional` вызывающий код применяет `FloorQty(raw, qtyStep)`:
`raw >= 0`, `qtyStep > 0`; результат равен точному
`floor(raw/qtyStep)*qtyStep` и никогда не повышает Qty. Проверка notional требует
`qty >= 0`, `price > 0`, `min >= 0` и сравнивает `qty*price >= min` точно.
Нулевой минимум отключает только порог notional; нулевое количество не является
разрешением заявки. Биржевые max/min Qty и order guards относятся к будущим
контрактам.

Здесь нет I/O, стратегии, ledger-проводок, P&L округления, хранения PostgreSQL
или торговых методов. D-01 остаётся открытым; эта арифметика не выбирает baseline
формулу и не задаёт golden targets.
