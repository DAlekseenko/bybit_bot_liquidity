## Топология и доверие

```text
Telegram → Hermes Messaging Gateway (внешний операторский процесс)
         → отдельный узкий MCP adapter в этом репозитории
         → аутентифицированный private Go Control API
           внутри Momentum trading process → application services
         → strategy / risk / execution / storage
```

Go владеет данными, формулами, планированием, состоянием, риском, исполнением и восстановлением. Поток намерения: planner → immutable `TradePlan` → отдельные confirmation/authorization gates → execution; MCP не подтверждает действие. MCP и Hermes не получают Bybit credentials, SQL, shell, произвольный HTTP, файлы или broker transport. API не обходит сервисы прямой записью в БД. Только execution engine может иметь broker trade transport.

Hermes MCP docs описывают stdio и remote HTTP/SSE, discovery и per-server tool filters; filter — UX defense, backend authorization остаётся обязательной. `identity_header` со статическим значением или именем профиля не удостоверяет Telegram actor и не доказывает человеческое подтверждение. Telegram gateway один; одновременно не запускаются два poller с одним bot token. Публичный MCP endpoint запрещён; remote transport требует отдельно gated TLS/private network.

## Общие типы и wire rules

Все MCP `inputSchema` и Control API JSON objects — `type: object`, перечисленные `properties`, обязательные поля в `required`, `additionalProperties: false`; nullable поля явно задаются `type: [T, "null"]`. Лишнее поле, неизвестная enum, неверный диапазон, тело сверх лимита или неизвестная версия — ошибка без побочного эффекта. Числа финансовых величин — decimal strings, не binary float. UTC timestamps — RFC3339; лимиты применяются до чтения хранилища. Идентификаторы 1..128 chars, body до 64 KiB, массивы до 100 элементов.

Типы: `Scope={strategy_id:string,environment:"PAPER"|"TESTNET"|"BACKTEST",run_id:string|null,account_ref:string|null}` (четыре поля); `Provenance={source_id:string,reference:string|null,revision:string|null,content_hash:string|null,verification:"VERIFIED"|"UNVERIFIED"}`; `Meta={scope:Scope,source:string|null,fetched_at_utc:string|null,freshness:"FRESH"|"STALE"|"UNAVAILABLE",completeness:"COMPLETE"|"PARTIAL"|"UNAVAILABLE"|"UNSUPPORTED",verification:"VERIFIED"|"UNVERIFIED",provenance:Provenance[],as_of_utc:string|null}`. `Meta.scope` берётся только из совпавшего backend grant. Нет источника — `source:null`, `provenance:[]`; не выдумывать source ID, revision или hash. Hash — lowercase hex SHA-256; отсутствующие reference/revision/hash — null. Provider сравнивает age с отдельно утверждённым `max_age`; без порога freshness `UNAVAILABLE`, непроверенная provenance остаётся `UNVERIFIED` и запрещает новые входы. `Error.code` включает `UNKNOWN` для результата, который после restart/reconciliation нельзя доказать; неподдержанный provider — `UNSUPPORTED`, отсутствующий/временно недоступный — `UNAVAILABLE`, устаревший — `STALE`. `Success<T>={ok:true,data:T,error:null,meta:Meta}`; `ErrorResult={ok:false,data:null,error:Error,meta:Meta|null}`; `Result<T>=Success<T>|ErrorResult`; `Error={code:enum,message:string(1..256),retryable:boolean,correlation_id:string}`. Каждый success требует Meta с доказанным Scope; `meta:null` допустим только при schema validation failure до auth или authentication/authorization denial до установления разрешённого Scope. После scope authorization error meta обязательна и основана на grant; pre-validation errors не отражают пользовательские scope/source IDs. Message без секретов.

Schema bounds: identifiers 1..128 chars, UTC strings RFC3339, `source` 1..64 chars, error message 1..256, arrays max 100. `Status={state:"RUNNING"|"PAUSED"|"STOPPED"|"UNAVAILABLE",paused:boolean,reason:string|null}`; `Position={symbol:string,side:"LONG"|"SHORT",quantity:decimal-string,entry_price:decimal-string,mark_price:decimal-string|null,unrealized_pnl:decimal-string|null}`; `Portfolio={equity:decimal-string|null,cash:decimal-string|null,positions:Position[]}`. `Performance={net_pnl:decimal-string|null,fees:decimal-string|null,funding:decimal-string|null,benchmark:decimal-string|null,coverage:string[]}`; no benchmark or fee source means null plus partial coverage.

`ConfigEntry={key:string(1..128),value:string|null}`, `ConfigView={version:string,values:ConfigEntry[],source:string}` expose allowlisted public settings only; provider/allowlist absent means `UNSUPPORTED`. `Signal={id:string,side:"LONG"|"SHORT"|"NONE",created_at_utc:string,state:string,price:decimal-string|null}`; `OrderView={id:string,state:"INTENT"|"ACKNOWLEDGED"|"PARTIAL"|"FILLED"|"REJECTED"|"UNKNOWN",filled_quantity:decimal-string|null,broker_operation_id:string|null}`. `RiskView={state:"READY"|"BLOCKED"|"UNAVAILABLE",checks:{name:string,state:"PASS"|"FAIL"|"UNKNOWN"}[],as_of_utc:string}`; `MarketView={prices:{symbol:string,price:decimal-string,as_of_utc:string}[],indicators:{name:string,value:decimal-string|null,as_of_utc:string|null}[],as_of_utc:string}`.

`PauseReceipt={paused:boolean,revision:string}`; `PauseState={paused:boolean,revision:string}`; `ConfigPatch={entries:ConfigEntry[]}`. `ResumePreview={kind:"RESUME",action_id:string,action_hash:string,scope:Scope,old_pause:PauseState,new_pause:PauseState,old_config:null,new_config:null,expected_revision:string,expires_at_utc:string,required_actor:string,effects:string[]}`; `ConfigPreview={kind:"CONFIG_CHANGE",action_id:string,action_hash:string,scope:Scope,old_pause:null,new_pause:null,old_config:ConfigPatch,new_config:ConfigPatch,expected_revision:string,expires_at_utc:string,required_actor:string,effects:string[]}`; `ActionPreview=ResumePreview|ConfigPreview`. Resume preview records `old_pause.paused:true` and `new_pause.paused:false`; config preview carries only config patches. Hash binds canonical kind/scope/old+new state/expected revision/actor/expiry. `ActionReceipt={state:"APPLIED"|"CANCELLED"|"PENDING",action_hash:string,revision:string}`; irreconcilable outcome is `Result` error `UNKNOWN`, never a successful receipt. `Job={job_id:string,run_id:string,state:"QUEUED"|"RUNNING"|"SUCCEEDED"|"FAILED"|"CANCELLED",input_hash:string}`; `JobStatus={job_id:string,state:Job.state,progress:int(0..100)|null}`; `Metrics={net_return:decimal-string|null,net_pnl:decimal-string|null,max_drawdown:decimal-string|null,trades:int|null,fees:decimal-string|null,funding:decimal-string|null,benchmark:decimal-string|null}`; `BacktestResult={job_id:string,input_hash:string,metrics:Metrics,coverage:string[],artifact_ref:string}`. Nested objects are closed; arrays max 100; schemas encode enums, nullability, lengths and bounds literally.

Доверенный auth envelope backend строит вне MCP args: `{principal_id,actor:{platform,user_id,chat_id},request_id,grants:[{role:"read"|"operate"|"admin",scope_type:"strategy"|"environment"|"run"|"account",strategy_id,environment,run_id,account_ref}],trusted_receipt:TrustedReceipt|null}`; `TrustedReceipt={receipt_id,action_id,action_hash,actor_id,scope:Scope,config_revision,expires_at_utc,nonce}`. Grant привязан к точным scope values; nullable run/account совпадают точно, wildcard запрещён. Требуется явная пара role + scope_type; `operate` не подразумевает `read`, `admin` этим реестром не выдаётся. Envelope никогда не является аргументом модели/tool. Trusted receipt выдаётся проверенным human callback вне model-controlled body, одноразово и с TTL; backend проверяет binding и hash против сохранённого canonical preview. Без валидного receipt подтверждение запрещено. `action_id` и `confirmation` — только lookup/reference strings; `confirmation` должен совпасть с `trusted_receipt.receipt_id`, но не является human proof.

## Реестр 17 операций

| № / tool | Строгие входы → `data` | Разрешение и ошибки сверх общих |
|---|---|---|
| 1 `get_status` | `{scope:Scope}` → `Status{state,paused,reason}` | `read:environment`; `UNAVAILABLE`,`STALE` |
| 2 `get_portfolio` | `{scope:Scope(account_ref nonnull)}` → `Portfolio{equity,cash,positions[]}` | `read:account`; `UNAVAILABLE`,`STALE` |
| 3 `get_positions` | `{scope:Scope(account_ref nonnull)}` → `Position[]` | `read:account`; `UNAVAILABLE`,`STALE` |
| 4 `get_performance` | `{scope:Scope(run_id nonnull),period:"1d"|"7d"|"30d"}` → `Performance{net_pnl,fees,funding,benchmark,coverage}` | `read:run`; `UNAVAILABLE`,`STALE` |
| 5 `get_strategy_config` | `{scope:Scope}` → `ConfigView{version,values,source}` | `read:strategy`; `UNAVAILABLE` |
| 6 `get_recent_signals` | `{scope:Scope(run_id nonnull),limit:int(1..100)}` → `Signal[]` | `read:run`; `UNAVAILABLE`,`LIMIT_EXCEEDED` |
| 7 `get_recent_orders` | `{scope:Scope(account_ref nonnull),limit:int(1..100)}` → `OrderView[]` | `read:account`; `UNAVAILABLE`,`LIMIT_EXCEEDED` |
| 8 `get_risk_status` | `{scope:Scope(account_ref nonnull)}` → `RiskView{state,checks[],as_of_utc}` | `read:strategy+account`; both grants exact, `UNAVAILABLE`,`STALE` |
| 9 `get_market_state` | `{scope:Scope}` → `MarketView{prices,indicators,as_of_utc}` | `read:environment`; `UNAVAILABLE`,`STALE` |
| 10 `pause_trading` | `{scope:Scope,reason:string(1..200),idempotency_key:string,expected_revision:string}` → `PauseReceipt{paused,revision}` | `operate:environment`; `CONFLICT`,`UNAVAILABLE`; only stops new entries, no cancel/close |
| 11 `prepare_resume` | `{scope:Scope,idempotency_key:string,expected_revision:string}` → `ResumePreview{old_pause:{paused:true,revision},new_pause:{paused:false,revision}}` | `operate:environment`; `CONFLICT`,`UNAVAILABLE`; preview only, never resumes |
| 12 `prepare_config_change` | `{scope:Scope,changes:ConfigPatch,idempotency_key:string,expected_revision:string}` → `ActionPreview` | `operate:strategy`; `CONFLICT`,`INVALID_ARGUMENT`; disabled until #146 defines key whitelist |
| 13 `confirm_action` | `{scope:Scope,action_id:string,confirmation:string,idempotency_key:string,expected_revision:string}` → `ActionReceipt{state,action_hash,revision}` | `confirmation` is an opaque receipt reference; stored kind RESUME→current `operate:environment`, CONFIG_CHANGE→current `operate:strategy`; `CONFLICT`,`STALE`,`FORBIDDEN` |
| 14 `cancel_action` | `{scope:Scope,action_id:string,idempotency_key:string,expected_revision:string}` → `ActionReceipt` | stored kind RESUME→current `operate:environment`, CONFIG_CHANGE→current `operate:strategy`; `NOT_FOUND`,`CONFLICT`,`FORBIDDEN` |
| 15 `run_backtest` | `{scope:Scope(run_id nonnull),dataset_id:string,strategy_version:string,config_version:string,start_utc:string,end_utc:string,idempotency_key:string}` → `Job{job_id,run_id,state,input_hash}` | `operate:run`; `CONFLICT`,`UNAVAILABLE`,`UNSUPPORTED`,`LIMIT_EXCEEDED`; validate scope, pinned provenance |
| 16 `get_backtest_status` | `{scope:Scope(run_id nonnull),job_id:string}` → `JobStatus{job_id,state,progress}` | `read:run`; verify stored strategy/environment/run/account tuple, `NOT_FOUND`,`UNAVAILABLE` |
| 17 `get_backtest_result` | `{scope:Scope(run_id nonnull),job_id:string}` → `BacktestResult{job_id,input_hash,metrics,coverage,artifact_ref}` | `read:run`; verify stored scope tuple, `NOT_FOUND`,`IN_PROGRESS`,`UNAVAILABLE`,`UNKNOWN` |

Каждая schema требует все показанные поля; nullable допускается только явно. `Scope` имеет ровно четыре поля. `run_id` непустой для run-scoped ops 4, 6, 15–17; `account_ref` непустой для account-scoped ops 2, 3, 7, 8; в иных случаях nullable и точно совпадает с grant. Wildcard/агрегация запрещены. Job сохраняет полный tuple strategy/environment/run/account; status/result сверяют его с запросом до чтения. Каждый nested object также `additionalProperties:false`. `ConfigPatch.entries` — массив до 100 закрытых `{key:string(1..128),value:string|null}`; backend принимает только отдельно утверждённые ключи. Whitelist не установлен до #146, operation 12 выключена. `idempotency_key` — обязательный 16..128 char ключ с durable uniqueness; `expected_revision` — обязательный точный CAS revision. Они не заменяются JSON-RPC `request_id`. Ключ связывается с principal, actor, operation, scope и canonical input hash; несовпадающий повтор даёт `CONFLICT`. `+` в permission требует обеих grants; `|` допускает только одну из указанных. `operate` не наследует `read`. `confirm_action`/`cancel_action` загружают immutable action; требуют полного совпадения переданного Scope с хранимым, trusted actor равного `required_actor` и текущего kind-specific grant именно на хранимый Scope (отзыв проверяется при вызове). Клиент не выбирает kind/role. Confirm требует одноразовый trusted receipt, связанный с `action_id`, `action_hash`, actor, полным Scope, config revision и TTL; backend сверяет hash с canonical stored preview. Тело запроса не подтверждает действие. Незнакомый/чужой ID возвращает одинаковый нераскрывающий `NOT_FOUND`/`FORBIDDEN`. Все enum поля — closed/versioned; неизвестное значение даёт `UNSUPPORTED`, без coercion. `FILLED` требует broker-operation evidence.

Mapping: `INVALID_ARGUMENT`/`UNAUTHENTICATED`/`FORBIDDEN`/`INTERNAL` → all; `NOT_FOUND` → 13–17; `CONFLICT` → 10–15; `STALE` → 1–4, 8–9, 13; `UNAVAILABLE`/`UNSUPPORTED` → any operation; `LIMIT_EXCEEDED` → 6, 7, 15; `IN_PROGRESS` → 10–15, 17 only (same idempotency key or running job); `UNKNOWN` → 10–15, 17 only when restart/reconciliation cannot prove outcome. Errors carry no financial data and always have `data=null`. Retry with the same key returns durable receipt or `IN_PROGRESS`; unprovable outcome returns `UNKNOWN`, blocking further mutation until reconciliation.

## Угрозы и ответ

| Угроза | Защита / fail-closed исход |
|---|---|
| Подмена actor моделью или profile header | Identity только из доверенного gateway envelope; нет bridge — deny operate/confirm. |
| Replay, crash/restart, повтор подтверждения | TTL, одноразовый durable receipt, idempotency key, CAS и atomic audit/command; пока не реализованы — critical mutations отключены, результат при timeout `IN_PROGRESS/unknown`. |
| SSRF / вредоносный endpoint | Endpoint фиксирован конфигурацией, allowlist host, запрет user URL/redirect и ambient proxy обхода; private network/TLS gate до remote. |
| Prompt injection из сообщений, market data, результатов | Весь внешний текст — data; backend schema/auth не зависит от текста модели; никаких shell/SQL/HTTP. |
| Второй Telegram poller или параллельные команды | Один владелец токена; backend сериализация/CAS и lease; duplicate side effect отклонён. |
| LLM/Hermes/Telegram outage | Go market loop автономен; pause доступна локально; outage сам не меняет позицию; устаревшие входные данные блокируют новые входы по Go policy. |
