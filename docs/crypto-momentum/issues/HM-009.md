# HM-009 — backend principal и authorization policy

Issue: [#138](https://github.com/DAlekseenko/bybit_bot_liquidity/issues/138). Связанный foundation: [#226](https://github.com/DAlekseenko/bybit_bot_liquidity/issues/226). Этот документ фиксирует pure policy backend; он не включает wire decoder, handler, runtime human issuer или выполнение команд.

## Principal и границы

`Principal` — закрытый неизменяемый снимок `kind` и grants. `NewServicePrincipal` принимает только доверенный backend контекст. `Actor()` отсутствует для service. Human policy требует proof-backed `HumanIdentity`; публичного issuer/conversion из Actor, JSON или model args нет. Нулевой principal неаутентифицирован. JSON principal отвергается. Foundation конструкторы проверяют идентификаторы, enum и весь список grants, ограничивают список 100 элементами и делают глубокую копию.

`Scope` сравнивается целиком: `StrategyID`, `Environment`, nullable `RunID`, nullable `AccountRef`. `nil` не равен заданной строке. Wildcard и наследование ролей не поддерживаются. `read`, `operate`, `admin` и `scope_type` должны совпасть явно. Успешный `Authorize` возвращает копию полного scope grant.

## Authorization mapping

| Operation | Required grant | Дополнительное условие |
|---|---|---|
| `get_status`, `get_market_state` | `read:environment` | — |
| `get_portfolio`, `get_positions`, `get_recent_orders` | `read:account` | `account_ref` задан |
| `get_performance`, `get_recent_signals` | `read:run` | `run_id` задан |
| `get_strategy_config` | `read:strategy` | — |
| `get_risk_status` | `read:strategy` и `read:account` | оба на одном полном scope; `account_ref` задан |
| `pause_trading` | `operate:environment` | только proof-backed human principal |

Pause policy только авторизует запрет новых входов; метод не исполняет команду и не создаёт receipt. Service principal всегда получает `ErrForbidden` на pause, даже при совпадающем operate grant. В репозитории нет runtime issuer для human identity, поэтому human pause capability в runtime недоступна.

Операции `prepare_resume`, `prepare_config_change`, `confirm_action`, `cancel_action`, `run_backtest`, `get_backtest_status`, `get_backtest_result` (HM-001 operations 11–17) отключены и всегда запрещены; для операций 15–17 отсутствующий `run_id` отклоняется раньше как некорректный scope. Неизвестная операция возвращает `ErrUnsupported`. Разрешённые read grants не открывают backtest операции.

## Ошибки и безопасность

Порядок отказа: invalid principal → `ErrUnauthenticated`; неизвестная операция → `ErrUnsupported`; неверный scope → `ErrInvalidArgument` или неизвестная среда → `ErrUnsupported`; отсутствующий обязательный selector → `ErrInvalidArgument`; известная отключённая операция → `ErrForbidden`; service pause → `ErrForbidden`; отсутствие любого точного grant → `ErrForbidden`. Любая ошибка возвращает нулевой `Scope` без идентификаторов.

Policy не обращается к Bybit, storage или сети и не меняет торговое состояние. Testnet и read-only ограничения сохраняются; paper/backtest не являются исполнением. Для реализации human gateway/receipt и любых команд нужны отдельные контракты и review.
